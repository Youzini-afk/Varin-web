一个扩展长什么样

把鼠标放到左边的条目上，右边会标出清单里对应的部分。

examples/extensions/agent-authored-panel/
varin.extension.json

一份契约。发现、激活、权限审查和工具 schema 都读它，不运行代码就能被发现。

身份入口服务与工具界面贡献
package.json

普通的 npm 元数据，版本与清单一致，可声明构建入口。

host.js

Host 端：工具、模型协议、上下文算法、Agent 策略。这里以 Brokered 方式运行在独立子进程里。

surface.cjs

界面端：面板、编辑器，乃至整套工作台。可以纯声明，也可以托管运行或放进隔离的 iframe、Worker。

panel.css · panel.svg

资源文件。图标、样式，或随包分发的可执行文件，都在不可变的包内解析。

import { defineHostExtension, provideTool } from '@varin/extension-sdk';
import manifest from './varin.extension.json' with { type: 'json' };
 
export default defineHostExtension({
  activate(context) {
    // 用清单里声明的同一个服务：发现和激活读的是同一份描述
    provideTool(context, manifest.provides.services[0], async (input, call) => {
      // 在新工具里调用内置工具，原回执完整保留
      const memory = await call.tools.invoke({
        callId: 'memory', name: 'memory', arguments: input.memory,
      });
      return { memory };
    });
  },
});

为什么这样设计

扩展再多，工作台也要稳、要可控。

一份清单就是契约

发现、激活、审查读的是同一份 varin.extension.json。没运行一行代码，扩展就能被发现、展示和检查。

读取工作区
调用工具
访问网络 · 待审

申请不等于授权

权限按版本、按运行层逐项审批。同一个扩展升级，不会顺带继承新权限；撤权立即生效。

先暂存，再一起发布

一次更新里的贡献、服务和状态一起生效。失败就留在上一代，不会只装上一半。

更新不打断任务

正在执行的调用固定在原来的实现上，直到完成；之后的调用才用新版本。

出了错，有边界

Brokered 扩展跑在独立子进程里，出错只收回它自己。选中的工作台起不来，还有恢复外壳兜底。

Agent 写的扩展已停用 · 待你审查你已启用

Agent 能写，不能自己批

Agent 可以读契约、写扩展、打包安装，但首次安装一律停用，等你审过再启用。

07 · Control

放手，不失控。
